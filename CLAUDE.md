# AGENTS.md

Operational context for coding agents working in this repo. Keep this file lean —
it is loaded into every session. Open work and settled decisions live in `docs/backlog.md`.

## What this is

A static, client-only map trainer for GeoGuessr-style geography, for France, Peru and Germany:
regions, departments, cities, rivers, landline phone zones and place-name endings (each
country offers only the topics worth drilling there). Each topic has a Learn mode (explore the map) and a Practice mode (several question types,
rounds, spaced repetition in a Leitner system kept in localStorage). The interface is in
English and Belarusian; Belarusian is the default (`?lang=en` for English). It began as a single-file claude.ai artifact. No backend. More countries will follow: the code is
country-agnostic and each country is a data folder. Deployed to GitHub Pages at
`https://nskurat.github.io/geoguessr-trainer/` by `.github/workflows/deploy.yml` on push to `main`.

Stack: Vite 8, TypeScript strict, Vitest 4 (node environment), ESLint 10 + typescript-eslint,
zod for data validation. No UI framework yet: the UI is the artifact's imperative DOM/SVG
code converted to TypeScript. Node >= 22.22.

## Commands

Run from the repo root. There is no nested `package.json`.

| Command | What it does |
|---|---|
| `npm run dev` | Vite dev server (root is `trainer-app/`), `http://localhost:5173` |
| `npm run build` | Builds into `dist/` |
| `npm run preview` | Serves the build at its real sub-path |
| `npm test` | Vitest, run once (`*.test.ts` in `__tests__/` folders) |
| `npm run test:coverage` | Coverage report |
| `npm run typecheck` | `tsc --noEmit` — must stay clean |
| `npm run lint` | ESLint over `trainer-app` and `scripts` — must stay clean |
| `npm run validate:data` | Zod schemas + referential checks for every country; exits non-zero on errors |
| `npm run build:outline -- <id>` | Outline + river courses from Natural Earth for a country |
| `npm run smoke -- [id…] [--shots] [--snapshot f] [--compare f]` | After `build`: browser smoke test of every set, language and question kind; screenshots; Learn-mode snapshot diff |

## Layout

```

scripts/validate-content.ts   Validates every country's data (npm run validate:data)
scripts/build-outline.ts      Builds a country's outline + river courses from Natural Earth
                              (npm run build:outline -- <country>; cache in .cache/, git-ignored)
trainer-app/
  index.html            Single page: header, control bar, map container, side panel
  src/
    main.ts             Entry: picks the language and country (?lang=, ?country=, last used...), loads, starts the trainer
    index.css           All styles; colour tokens on :root with light/dark themes
    app/trainer.ts      The imperative UI (map rendering, pan/zoom, controls, practice flow, panel).
                        Temporary shape: to be split into components in the planned React port
    types/geo.ts        Country-agnostic data types (Country, Region, Department, City, River, ...)
    types/trainer.ts    StudySet, Mode, QuestionKind, Outcome
    types/i18n.ts       LANGS (interface languages), Lang, Message, PluralForms
    i18n/               en.ts (source strings, defines the keys), be.ts, index.ts (t/th, active
                        language, data-i18n in index.html), README.md (Belarusian terms + sources)
    data/countries.ts   Registry of countries (each loads lazily); picked by ?country=<id>
    data/<country>/     JSON data + index.ts exporting the Country: offered study sets, projection,
                        label nudges; copy.<lang>.ts per interface language (terms, tips,
                        credits, translations of the data's English text). France: outline
                        from npm; Peru, Germany: outline.json generated by scripts/build-outline.ts
    services/country/   countryIndex.ts (lookups and localized data for one language), schema.ts (zod + validateCountry)
    services/i18n/      format.ts (interpolation, Intl.PluralRules plurals), negotiate.ts (URL → saved → default; the site defaults to Belarusian)
    services/geo/       projection.ts (fit lat/lon -> SVG affine projection from anchors; haversine)
    services/practice/  spacedRepetition (Leitner boxes), round (queue, scoring, requeue misses),
                        distractors (multiple-choice options), scoring (distance bands), settings
    services/storage/   trainerStorage.ts: TrainerStorage adapter, localStorage impl with memory fallback
    utils/              random (shuffle with injectable rng), html (escapeHtml), svgPath (smoothPath)
```

## Conventions

- TypeScript strict; `tsc --noEmit` and lint must stay clean. No new `any`.
- Pure logic (scheduling, scoring, projection, distractors, round queue) lives in
  `services/` or `utils/` as side-effect-free modules **with unit tests**, with rng and
  time injectable for determinism. The UI layer stays thin.
- New external data or storage goes behind an adapter interface — see
  `services/storage/trainerStorage.ts` for the pattern.
- Country data is data only. The trainer code never names a country; country-specific
  text lives in each `data/<country>/copy.<lang>.ts`.
- No user-visible string literals in `app/` or `index.html`: use `t()`/`th()` and keys in
  `i18n/en.ts` (see "Interface languages").
- Paths are never hardcoded — derive from `import.meta.env.BASE_URL`.
- UI/UX follows the original artifact's design (tricolore-blue accent, Archivo font,
  road-atlas look, CSS custom-property colour tokens with light/dark themes in
  `src/index.css`), not the Nihongo repo's style.

## Constraints

- **Data JSON is hand-curated study data**, approximate and not survey-grade. Change it
  deliberately and keep `npm run validate:data` clean.
- **Attribution is a licence requirement.** Département outlines are "France departments
  map" by Victor Cazanave (svg-maps, npm `@svg-maps/france.departments` v1), CC BY 4.0 —
  the credit line in the page footer must stay. Phone zones follow the Wikipedia table
  of French area codes. Germany's town coordinates are GeoNames, CC BY 4.0 — its footer
  credit must stay too.
- The app is served from the `/geoguessr-trainer/` sub-path (`vite.config.js` `base`;
  `VITE_BASE_PATH` overrides). Never hardcode paths.
- Progress and settings live in the user's localStorage, per country
  (`geotrainer_<country>_progress`). No backend, telemetry or key transmission.

## Adding a country

Follow the `add-country` skill (`.claude/skills/add-country`): it sequences these steps,
with the gates where to stop and ask on the issue.

1. Ask the `geoguessr-pro` skill for a country brief: which study sets are worth drilling
   (only those go in `sets`), the top-level grouping, and what each data file needs.
2. Outline: an `@svg-maps` package with matching ids, or add the country to `COUNTRIES` in
   `scripts/build-outline.ts` and run `npm run build:outline -- <id>` (Natural Earth, public
   domain; it also writes river courses and the exact projection `affine`).
3. Data in `data/<id>/` (same shapes as France), sourced; keep notes in the folder
   (e.g. `RESEARCH.md`). Export the `Country` from `data/<id>/index.ts`, add it to
   `data/countries.ts` and `scripts/validate-content.ts`, and keep `npm run validate:data` clean.
   Write `copy.<lang>.ts` for every interface language.
4. Check it in the browser with the `ux-expert` skill's Playwright routine (light and dark,
   1280 and 390 px, every language), then compare France is unchanged.

## Interface languages

- `types/i18n.ts` `LANGS` lists the languages; `en` is the source and fallback.
- Interface strings: one file per language in `i18n/`. `en.ts` defines every key; other
  languages are typed `Messages`, so a missing key is a type error. `{param}` placeholders;
  number-dependent messages are CLDR plural objects (`one`/`few`/`many`/`other`) picked by
  `count`. `th()` keys are trusted HTML with escaped parameters. Static text in
  `index.html` uses `data-i18n` / `data-i18n-aria`.
- Country text: `data/<country>/copy.<lang>.ts`, combined as `Country.copy: Record<Lang,
  CountryCopy>` and lazy-loaded with the country (a few KB next to the outlines, and the
  live switch needs no extra load). Each copy holds the terms (`Term.counted` for forms
  after numerals), set labels, tips, credits and `data`: translations of the JSON's English
  text (phone zones, name patterns, rivers) by id. `indexCountry(country, lang)` applies it.
- Place names are never translated; only country names, seas and English exonyms are.
- `npm run validate:data` fails if a country lacks copy for a language, a set label or tip,
  a `data` translation of any zone, pattern or river, or if `data/countries.ts` names differ
  from `copy.<lang>.countryName`.
- Adding a language: add it to `LANGS`, add `i18n/<lang>.ts` (typed `Messages`) and its
  loader in `i18n/index.ts` `LANGUAGES`, a `copy.<lang>.ts` per country and its name in
  `data/countries.ts`; typecheck and `validate:data` list everything missing. Check plural
  forms with `Intl.PluralRules(<lang>)` and record term choices in `i18n/README.md`.
